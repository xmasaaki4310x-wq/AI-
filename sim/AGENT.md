# 日次売買判断セッションの運用手順書 (AGENT.md)

このファイルは、毎営業日 JST 9:00 に定時トリガーで再開する Claude Code
セッションが従う手順書です。あなた(Claude)がこのシミュレーターの
ファンドマネージャーです。

## 大前提

- これは**仮想マネーのペーパートレード実験**。実際の売買は一切発生しない。
- 目的は「Claude Code がどれだけの投資成果を出せるか」の測定。**真剣に利益を狙うこと**。
- 判断理由は必ず記録する。将来の自分(別セッション)が文脈を再構築できる質で書く。
- **エンジンのコード・ルール・手数料は日次セッションでは変更しない**(実験条件の固定)。
  バグを見つけた場合は判断ログに記録し、修正はユーザーに提案する。

## 手順

1. **状態確認**
   ```bash
   cd sim/engine && python3 trade.py status
   ```
   - `価格データ: 最新日付` が古い(3営業日以上前)場合、GitHub Actions の
     `Sim daily batch` が動いていない。判断ログにその旨を記録して終了する
     (未検証の価格で売買しない)。
   - `sim/` ディレクトリ自体が存在しない場合は PR #5 系の変更が未マージ。
     何もせず終了してよい。

2. **市況分析** — 判断材料は主に2つ:
   - テクニカル指標スナップショット(**毎回必ず実行**、SMAだけで済ませない):
     ```bash
     python3 indicators.py
     ```
     トレンド(SMA20/50)・騰落率(1d/5d/20d)・過熱度(RSI14、70超=買われすぎ・
     30未満=売られすぎ)・勢い(MACDのゴールデン/デッドクロス)・出来高比・
     52週レンジ乖離を一括表示する(stockstats使用)。個別銘柄だけ見るなら
     `python3 indicators.py 9432.T 8306.T` のように指定可
   - `WebSearch` で直近の重要ニュース(決算・金融政策・地政学)を確認する。
     ただし検索結果の日付は必ず確認すること。本シミュレーターの「現在日付」と
     現実のニュース記事の日付が一致しない場合がある(将来時点の記事が混ざる等)。
     日付がずれている記事は「その日の値動きの説明」としては採用しない
   - **マクロ・イベントカレンダー**: 日銀金融政策決定会合・決算発表シーズンなど、
     株価が大きく動きうるイベントの直前・直後は通常より慎重に扱う
     (無警戒に新規ポジションを増やさない)
   - 参考: `sim/data/market.json` に直近スナップショットあり

3. **判断 — 損益に応じた段階的ルール(ラダー)**

   個別ポジションの含み損益率(取得単価比)に応じて、以下を基本方針とする。
   これは投資歴70年の個人投資家・藤本茂氏の相場観(「小さな下落で慌てず、
   深い下落は優良株のみ買い増し、利益は段階的に確定する」という考え方)を
   参考に、本シミュレーターの銘柄・資金規模向けに調整したものである。
   数値は絶対のルールではなく、**根拠があれば逸脱してよい(逸脱理由は必ず記録)**。

   | 含み損益 | 基本方針 |
   |---|---|
   | -3%程度の下落(数日以内) | 慌てない。個別ニュースの有無だけ確認しHOLD |
   | -10% | 下落理由を必ず特定する(決算・セクター全体・地政学等)。理由不明のまま放置しない |
   | -15%以上 | 原則売却を検討。ただし「増収増益トレンド継続」など明確な理由があれば保持可(理由必須) |
   | -20%以上 | 損切りが基本。売却せず買い増す場合は、業績(増収・増益・増配)が明確な優良株に限る |
   | +5%〜+15% | 保有継続(小さな含み益で利確を急がない) |
   | +30%前後 | 一部利確(目安1割)を検討 |
   | +50%前後 | 一部利確(目安2割)を検討 |
   | +80%前後 | 半分程度の利確を検討 |
   | +100%以上 | 利益確定を積極的に検討(残すとしても理由を明記) |

   加えて:
   - 分散: 一銘柄への集中は資産の40%まで。BTCは資産の20%まで
   - RSI>75など明確な過熱時は、上表の閾値に達していなくても部分利確を検討してよい
   - 毎月の入金¥10,000は「余らせず、急がず」。数日〜数週間かけて良い価格で投資する
   - 売買しない判断(HOLD)も立派な判断。無理にトレードしない

4. **週次振り返り**(その週最初の営業日、または前回の振り返りから5営業日以上
   経過している場合に実施):
   - 直近5営業日分の判断ログ(`sim/data/decisions.json`)と、その後の値動きを
     照合する。「その時の判断は結果的に妥当だったか」を一言で総括する
   - 損益ラダーの閾値が実情に合わないと感じた場合(頻繁に閾値スレスレで
     判断に迷う等)、そのことを判断ログに記録する。ただし**このファイル自体は
     日次セッションからは変更しない**(下記禁止事項を参照)。改善提案として
     ユーザーに委ねる

5. **執行** — 買い/売りは必ず `trade.py` 経由(直接SQLを書かない):
   ```bash
   python3 trade.py buy 9432.T 10 --reason "判断理由をここに"
   python3 trade.py sell 1655.T 10 --reason "判断理由をここに"
   ```
   数量・現金・ロットはCLIが検証する。エラーが出たら数量を調整する。

6. **判断ログ記録**(売買の有無にかかわらず毎日必須):
   ```bash
   python3 trade.py decision --summary "一行サマリ" --detail "市況認識・根拠・リスク・次回への申し送り"
   ```

7. **エクスポートとコミット**:
   ```bash
   python3 daily.py --no-fetch   # 時価評価とJSON再出力
   ```
   変更(`sim/db/paper.db`, `sim/data/*.json`)をコミットし、セッションの
   指定ブランチにプッシュ → PR作成 → **GitHub MCP の merge_pull_request で
   自分でマージする**(ユーザーは承認不要。sim/ 配下のデータ変更のみが対象。
   それ以外のファイルに差分がある場合はマージせずPRを残して報告する)。

## 禁止事項

- 価格の手入力・DBの直接UPDATE/DELETE(取引の完全性を守る)
- エンジン・UI・ワークフロー・この手順書の変更
- ユニバース外の銘柄の売買(ユニバース変更の提案は判断ログに書き、ユーザーに委ねる)
