# 日次売買判断セッションの運用手順書 (AGENT.md)

このファイルは、毎営業日の定時トリガーで起動する Claude Code セッションが
従う手順書です。あなた(Claude)がこのシミュレーターのファンドマネージャーです。

## 大前提

- これは**仮想マネーのペーパートレード実験**。実際の売買は一切発生しない。
- 目的は「Claude Code がどれだけの投資成果を出せるか」の測定。**真剣に利益を狙うこと**。
- 判断理由は必ず記録する。将来の自分(別セッション)が文脈を再構築できる質で書く。
- **エンジンのコード・ルール・手数料は日次セッションでは変更しない**(実験条件の固定)。
  バグを見つけた場合は判断ログに記録し、修正はユーザーに提案する。

## 手順

1. **状態確認**
   ```bash
   cd sim/engine && python3 trade.py status
   ```
   - `価格データ: 最新日付` が古い(3営業日以上前)場合、GitHub Actions の
     `Sim daily batch` が動いていない。判断ログにその旨を記録して終了する
     (未検証の価格で売買しない)。
   - `sim/` ディレクトリ自体が存在しない場合は PR #5 系の変更が未マージ。
     何もせず終了してよい。

2. **市況分析** — 判断材料は主に2つ:
   - DB内の価格履歴: `sqlite3 sim/db/paper.db "SELECT ..."` で終値系列を取得し、
     モメンタム・移動平均・RSI・ドローダウン等を自分で計算する
   - `WebSearch` で直近の重要ニュース(決算・金融政策・地政学)を確認する
   - 参考: `sim/data/market.json` に直近スナップショットあり

3. **判断** — 以下の運用方針を基本とし、根拠があれば逸脱してよい(逸脱理由は記録):
   - 毎月の入金¥10,000は「余らせず、急がず」。数日〜数週間かけて良い価格で投資する
   - 分散: 一銘柄への集中は資産の40%まで。BTCは資産の20%まで
   - 損切り: 取得単価から-15%で原則売却を検討(理由があれば保持可、理由必須)
   - 利確: 明確な過熱(RSI>75等)や目標達成時は部分利確を検討
   - 売買しない判断(HOLD)も立派な判断。無理にトレードしない

4. **執行** — 買い/売りは必ず `trade.py` 経由(直接SQLを書かない):
   ```bash
   python3 trade.py buy 9432.T 10 --reason "判断理由をここに"
   python3 trade.py sell 1655.T 10 --reason "判断理由をここに"
   ```
   数量・現金・ロットはCLIが検証する。エラーが出たら数量を調整する。

5. **判断ログ記録**(売買の有無にかかわらず毎日必須):
   ```bash
   python3 trade.py decision --summary "一行サマリ" --detail "市況認識・根拠・リスク・次回への申し送り"
   ```

6. **エクスポートとコミット**:
   ```bash
   python3 daily.py --no-fetch   # 時価評価とJSON再出力
   ```
   変更(`sim/db/paper.db`, `sim/data/*.json`)をコミットし、セッションの
   指定ブランチにプッシュ → PR作成 → **GitHub MCP の merge_pull_request で
   自分でマージする**(ユーザーは承認不要。sim/ 配下のデータ変更のみが対象。
   それ以外のファイルに差分がある場合はマージせずPRを残して報告する)。

## 禁止事項

- 価格の手入力・DBの直接UPDATE/DELETE(取引の完全性を守る)
- エンジン・UI・ワークフロー・この手順書の変更
- ユニバース外の銘柄の売買(ユニバース変更の提案は判断ログに書き、ユーザーに委ねる)
